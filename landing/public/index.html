Tickets in. Reviewed commits on main out.

Holophyte claims a ticket from your board, has an agent implement it in an isolated git worktree, holds it to the ticket's verify commands and an independent review, and lands it on main.

One ticket, five steps

  1. 01Claim

    The next Ready ticket whose dependencies have merged. Its body becomes the contract.

  2. 02Implement

    An agent works and commits in its own git worktree, optionally in a container.

  3. 03Verify

    The ticket's own verify commands run on the candidate.

  4. 04Review

    An independent reviewer judges the diff and witnesses each criterion.

  5. 05Land

    A merge to main, or a pull request watched through its checks.

Built to be trusted unattended

  • Witnessed criteria

    The reviewer marks each acceptance criterion met, not met or unwitnessed, and anything short of met blocks approval.

  • Adversarial review

    Optionally, a second reviewer tries to break the candidate while the first checks it against the ticket.

  • Isolation

    The implementer works in its own worktree, optionally in a container; the reviewer gets a read-only copy with no host credentials.

  • Steer a live run

    Send a note from the run page or holo steer and the agent reads it at its next turn.

  • The store is the record

    Every claim, round, finding, steer and merge is a row in one SQLite store per project, and the console renders from it.

The screens are the real console over a seeded demo store; the tickets, runs and pull requests are fixture data.
